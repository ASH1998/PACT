# Code of Conduct

PACT contributors and maintainers are expected to keep the project professional,
welcoming, and focused on building a trustworthy open-source security tool.

## Expected Behavior

- Be respectful and constructive in issues, pull requests, reviews, and chats.
- Assume good intent, but ask for clarification when behavior or wording is
  unclear.
- Discuss technical disagreements with evidence, reproduction steps, and tradeoffs.
- Give extra care to security reports, privacy-sensitive details, and disclosure
  timing.
- Credit prior work and avoid misrepresenting the project's maturity or security
  guarantees.

## Unacceptable Behavior

- Harassment, threats, personal attacks, or discriminatory language.
- Publishing private vulnerability details before maintainers have had a chance
  to triage and coordinate.
- Sharing secrets, private keys, personal data, or confidential logs without
  permission.
- Repeatedly derailing technical discussions after maintainers ask to return to
  scope.
- Spam, impersonation, or other bad-faith participation.

## Enforcement

Maintainers may warn, moderate, hide, or remove comments and may restrict
participation for behavior that violates this code. Enforcement should be
proportionate, documented privately when practical, and focused on protecting
contributors and users.

For conduct concerns, contact a maintainer privately through GitHub. If the
concern involves private vulnerability details or sensitive safety information,
use the private process in `SECURITY.md`.

For urgent safety or vulnerability concerns, use the private process in
`SECURITY.md` instead of a public issue.
